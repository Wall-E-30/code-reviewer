# Aion-Bench Public Leaderboard: Submission Guide (LAUNCH-03, GROWTH-02)

**Benchmark Standard:** `bench_real` (Real-World Pull Request Code Review Benchmark)  
**Evaluation Harness:** `python -m bench_real`  
**License:** Apache 2.0  

---

## 1. Overview & Evaluation Principles

The **Aion-Bench Leaderboard** tracks state-of-the-art automated code review systems (open-weight models, commercial frontier LLMs, and static analysis pipelines) evaluated on real open-source pull requests.

We adhere strictly to Non-Negotiable Rule #2 ("Never fake data"):
- **Zero Synthetic Disguise:** Evaluation must run on real pull requests (`bench_real`) containing verified bug fixes, reverts, CVEs, and clean negatives.
- **Strict Negative Controls:** Every benchmark evaluation includes clean-diff negatives ($25\%$ of split) to penalize false-positive spamming.
- **Statistical Significance:** All metrics must report non-parametric bootstrap $95\%$ confidence intervals ($1,000$ resamples).
- **Public Reproducibility:** Open-weight submissions must provide public Hugging Face weights or Ollama recipes; commercial API submissions must provide executable runner scripts with exact model IDs and hyperparameters.

## 2. Submission Format (`submission.json`)

Submissions are packaged as a JSON document containing model metadata and generated review predictions:

```json
{
  "submission_version": "2.0.0",
  "model_name": "MyOrg-CodeReview-7B",
  "organization": "MyOrg",
  "model_type": "open-weights",
  "base_model": "Qwen/Qwen2.5-Coder-7B-Instruct",
  "parameters": "7B",
  "license": "Apache-2.0",
  "artifact_url": "https://huggingface.co/MyOrg/MyOrg-CodeReview-7B",
  "contact_email": "maintainers@myorg.example",
  "predictions": [
    {
      "case_id": "val-aiohttp-bug-01",
      "comments": [
        {
          "file_path": "aiohttp/client.py",
          "line_number": 142,
          "category": "security",
          "comment": "Unsanitized user input passed to header formatter creates potential response splitting.",
          "suggestion": "formatted_header = sanitize_header(user_header)",
          "confidence": 0.89
        }
      ]
    }
  ]
}
```

### Schema Requirements
- `case_id` (string, required): Matches the case identifier in `bench_real/splits/val.json`.
- `comments` (array, required): List of review comments generated by the model.
  - On clean diffs, models that output an empty list (`"comments": []`) are scored positively.
  - At most 5 comments per case are evaluated (excess comments are penalized as spam).
- `suggestion` (string, optional): Valid 1-click replacement code block.

## 3. Running Local Evaluation

Before submitting, verify your submission against the validation split using the official runner:

```bash
# 1. Activate Python environment
python -m venv .venv
source .venv/bin/activate  # Or Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt

# 2. Evaluate your submission file
python -m bench_real --split val --submission path/to/submission.json --output results.json

# 3. Inspect generated metrics
cat results.json
```

### Official Evaluation Metrics
The evaluator computes:
1. **Precision:** $\frac{\text{True Positives}}{\text{True Positives} + \text{False Positives}}$ (greedy bipartite matching within $\Delta \le 3$ lines).
2. **Recall:** $\frac{\text{True Positives}}{\text{Ground-Truth Defects}}$.
3. **Clean-Diff FPR:** $\frac{\text{Cases with False Positives}}{\text{Total Clean PR Cases}}$.
4. **Nitpick Rate:** Proportion of comments flagged as subjective styling rather than verifiable bugs.
5. **Mean Comments / PR:** Average volume of comments per diff.

## 4. Submission Pull Request Workflow

1. **Fork the Repository:** Fork `https://github.com/Wall-E-30/code-reviewer`.
2. **Create a Submission Branch:**
   ```bash
   git checkout -b submission/<your-model-name>
   ```
3. **Place Submission Assets:**
   - Place your `submission.json` under `bench_real/submissions/<model_name>.json`.
   - Add model metadata to `data/leaderboard.json`.
4. **Run Verification:**
   ```bash
   python scripts/launch_gate_check.py
   ```
5. **Open Pull Request:**
   - Title: `[Leaderboard Submission]: <Model Name>`
   - Description must include reproducibility instructions, hardware used, and licensing confirmation.
   - GitHub Actions CI will automatically evaluate your predictions against the locked test split (`bench_real/splits/test_locked.json`) and append your score to the official leaderboard upon merge.
